01 Introducción: El Verdadero Coste de la Inteligencia

📊

Gestión de tokens como decisión de diseño

No es contabilidad, es estrategia

Como Arquitecto de Sistemas IA, la gestión de tokens no es un ejercicio de contabilidad, sino una decisión de diseño estratégico. Optimizar el uso de tokens en Claude Code no solo protege tu presupuesto; mejora la "agilidad mental" del modelo al reducir el ruido informativo. Un contexto saturado es un contexto lento y propenso a errores.

INFO · Fuente del gasto Debemos desmitificar la fuente del gasto: el 99.9% de tu consumo no proviene de lo que escribes. De hecho, tus prompts representan apenas el 0.01% del total.

El verdadero "vampiro" de recursos es la arquitectura subyacente. Según datos técnicos de sesiones reales, el 96% del gasto total proviene de la relectura constante del historial.

Objetivo de la guía Esta guía te enseñará a gestionar el Contexto (la memoria de corto plazo de Claude) para evitar límites de sesión y maximizar el rendimiento mediante el aprovechamiento del sistema de caché de Anthropic.

02 Auditoría de Tokens en Tiempo Real

🔍

El Primer Paso: Diagnóstico

Datos duros, no estimaciones vagas

Antes de aplicar cualquier optimización, un arquitecto debe realizar un diagnóstico. No podemos basarnos en estimaciones vagas; necesitamos datos duros.

El Prompt Maestro

Copia y pega exactamente esto. Este prompt está diseñado para obligar a Claude a inspeccionar sus propios procesos internos y reportar "puntos de fuga" con precisión numérica.

Audit this setup for token waste. Do not fix anything. Report only.
Use your shell and file tools to measure each item. If you cannot invoke slash
commands yourself, ask me to run /context and /usage and paste the output, then
continue.

1. MEMORY: Find every CLAUDE.md in scope: this project, parent directories, the user
level one, and anything pulled in with @imports. Report each file's size in
tokens. Flag any single file over 5k and any total over 10k.

2. TOOLS: List connected MCP servers and how many tools each exposes. State plainly
whether tool deferral is ACTIVE or NOT. Then check for a proxy or gateway
(ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN, any gateway variable) and say so
loudly if you find one, because routing through a proxy silently turns
deferral off and nothing warns you.

3. MODEL: Report the current model and effort level and where each is set. Flag any
mode that changes model automatically during a session, because every
switch rebuilds the whole cache.

4. HOOKS: List any PreToolUse hooks that rewrite noisy commands to produce less
output. If there are none, say so, because unfiltered test and build output
lands in context verbatim and is re-sent for the rest of the session.

5. SUBAGENTS: List every agent file in the project and user agent directories. For each,
report whether it sets an explicit model in frontmatter or inherits the
main session's model.

6. SCHEDULED WORK: List every cron, scheduled task and background job with its interval.
Compare each interval against the prompt cache lifetime (60 min). Flag every one
whose interval is longer, because those miss cache on every single fire.

7. CACHE: Parse the newest session log under the projects directory. For every
assistant turn, sum usage.cache_read_input_tokens,
cache_creation_input_tokens, input_tokens and output_tokens. Report each as
a percentage of the total. Also report the context size on the first turn
and on the last turn.

Output one table, sorted by cost, highest first:
FINDING | SEVERITY | EVIDENCE | WHAT IT IS COSTING ME

Severity is RED, AMBER or GREEN. Evidence is a number or a file path, never an
adjective.
Then one final line: the single highest-leverage change I should make. One
line, nothing else.
Rules: measure, do not estimate. Write UNKNOWN rather than guessing. Change no
file and no setting.

7 puntos de auditoría

1. MEMORY — Archivos CLAUDE.md▶
Busca cada CLAUDE.md en alcance: proyecto, directorios padre, nivel de usuario y cualquier cosa importada con @imports. Reporta el tamaño de cada archivo en tokens. Marca cualquier archivo individual por encima de 5k y cualquier total por encima de 10k.
2. TOOLS — Servidores MCP y deferral▶
Lista los servidores MCP conectados y cuántas herramientas expone cada uno. Indica claramente si tool deferral está ACTIVO o NO. Después comprueba si hay un proxy o gateway (ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN, cualquier variable de gateway) y dilo en voz alta: enrutar a través de un proxy desactiva el deferral silenciosamente sin avisarte.
3. MODEL — Modelo y nivel de esfuerzo▶
Reporta el modelo actual y el nivel de esfuerzo (effort level) y dónde se define cada uno. Marca cualquier modo que cambie de modelo automáticamente durante la sesión, porque cada cambio reconstruye todo el caché.
4. HOOKS — PreToolUse▶
Lista cualquier hook PreToolUse que reescriba comandos ruidosos para producir menos salida. Si no hay ninguno, dilo, porque la salida sin filtrar de tests y builds aterriza en el contexto textualmente y se reenvía durante el resto de la sesión.
5. SUBAGENTS — Archivos de agente▶
Lista cada archivo de agente en los directorios de proyecto y de usuario. Para cada uno, reporta si establece un modelo explícito en el frontmatter o si hereda el modelo de la sesión principal.
6. SCHEDULED WORK — Tareas programadas▶
Lista cada cron, tarea programada y job en segundo plano con su intervalo. Compara cada intervalo contra la vida del caché de prompt (60 min). Marca cada uno cuyo intervalo sea mayor, porque esos pierden el caché en cada ejecución.
7. CACHE — Log de sesión▶
Parsea el log de sesión más reciente bajo el directorio de proyectos. Para cada turno del asistente, suma usage.cache_read_input_tokens, cache_creation_input_tokens, input_tokens y output_tokens. Reporta cada uno como porcentaje del total. También reporta el tamaño del contexto en el primer turno y en el último.

Formato de salida exigido

ColumnaDescripción
FINDINGHallazgo detectado
SEVERITYRED / AMBER / GREEN
EVIDENCEUn número o una ruta de archivo, nunca un adjetivo
WHAT IT IS COSTING MECoste asociado al hallazgo

Ordenada por coste, mayor primero. Después una línea final: el único cambio de mayor palanca que debo hacer. Una línea, nada más.

Reglas del prompt Medir, no estimar. Escribir UNKNOWN en lugar de adivinar. No cambiar ningún archivo ni ningún ajuste.
Cadencia recomendada Vuelve a ejecutar la auditoría cada vez que añadas un plugin, servidor MCP, tarea programada o archivo de instrucciones importante. Los pequeños cambios de configuración se acumulan rápidamente.

03 Estrategia 1: El Comando /clear y el Arte del Reinicio

🧹

El historial es interés compuesto

Cada mensaje reenvía toda la conversación anterior

En Claude Code, el historial no es un registro pasivo; es interés compuesto. Debido a que el modelo no tiene memoria intrínseca, cada vez que envías un mensaje, Claude "empaqueta" toda la conversación anterior y la reenvía.

Mecánica del Gasto: La Caja Plateada

Tu mensaje actual es una pequeña "caja plateada" en la parte superior. Todo lo que está debajo es historia por la que ya pagaste, pero que vuelves a pagar en cada nuevo turno.

Ejemplo de multiplicación Un archivo de 3,000 tokens leído en el turno 4 de una sesión de 40 turnos te costará ese valor multiplicado por 37.

Acción Paso a Paso

  1. Ejecuta /clear: Al terminar una tarea y empezar otra, limpia la sesión. Esto resetea el historial al 0% inmediatamente.
  2. Gestiona con /rename y /resume: Si temes perder información, usa /rename para archivar la sesión actual. Podrás recuperarla con /resume si es urgente. No tires el trabajo; simplemente deja de cargarlo innecesariamente.

Comparativa de escenarios

EscenarioCoste de HistorialEstado del Caché
Continuar sesión viejaMáximo (Acumulativo)Cálido (pero saturado)
Sesión nueva con /clearCeroEmpty/Cold (Ligero)

04 Estrategia 2: Estabilidad del Modelo y el "Cache Key"

🔐

La llave del caché

Hasta 90% de ahorro en costes de lectura

La clave para ahorrar hasta un 90% en costes de lectura es el Caché de Prompt. Sin embargo, este sistema es extremadamente sensible.

La Llave del Caché (Cache Key)

Imagina que el caché es una bóveda. La "llave" para abrirla está compuesta por:

Cache Key [Nombre del Modelo] + [Nivel de Esfuerzo] + [Configuración de Servidores MCP]

Si cambias un solo componente, la llave ya no encaja y el caché se invalida.

El Error del Ahorrador Bajar de Opus a Sonnet a mitad de sesión para "ahorrar" es la acción más cara que puedes realizar. Al cambiar el modelo, Claude debe re-procesar todo el historial a precio completo (10 veces más caro que una lectura de caché).

Acciones Peligrosas (Rompen el Caché)

  • Cambiar de modelo (/model).
  • Cambiar nivel de esfuerzo (effort level).
  • Activar fast mode.
  • Actualizar Claude Code (un update a mitad de sesión invalida el caché).
  • Compactar la sesión.

Acciones Seguras

  • Editar archivos en el repo.
  • Modificar archivos de memoria (CLAUDE.md).
  • Invocar subagentes.
  • Cambiar el estilo de salida.
Consejo Pro Elige tu configuración al inicio y no la toques hasta el próximo /clear.

05 Estrategia 3: Gestión de Herramientas y Servidores MCP

🛠️

Cada herramienta carga su manual

GitHub solo puede ocupar 26,000 tokens antes de tu "Hola"

Cada herramienta conectada (GitHub, Slack, etc.) carga su manual de instrucciones en el contexto. GitHub solo puede ocupar 26,000 tokens antes de que digas "Hola".

El Peligro del Proxy

Claude utiliza una técnica llamada "Tool Deferral" (Carga diferida) que mantiene estos manuales cerrados hasta que se necesitan.

Advertencia Crítica Si utilizas un proxy o gateway (configurando ANTHROPIC_BASE_URL), el sistema desactiva el deferral silenciosamente. Pagarás por todos los manuales de herramientas en cada mensaje sin aviso previo.

Acciones

  1. Usa /mcp y apaga cualquier herramienta que no hayas usado en el último mes.
  2. Usa /context y verifica que en la línea de herramientas aparezca el estado "deferred".

06 Estrategia 4: Filtros de Salida (PreToolUse Hooks)

🎛️

El Filtro Maestro

50,000 tokens → 200 tokens útiles

Cuando instalas una librería, la terminal puede escupir 800 líneas de advertencias y logs. Si no se filtran, esas líneas ensucian tu contexto permanentemente.

Solución Debes crear un "filtro" que resuma la salida antes de que llegue al modelo. Pide a Claude lo siguiente: 
"Create a PreToolUse hook script that intercepts terminal output. If a command generates more than 20 lines of logs, summarize it to 'Success' or 'Error' plus the last 5 lines. Save it as a hook for this environment."
Resultado Esto transforma 50,000 tokens de "basura de instalación" en 200 tokens de información útil.

07 Estrategia 5: Subagentes y el Dilema de la Delegación

🤖

Los subagentes no ahorran tokens, los mueven

La realidad arquitectónica

Muchos creen que los subagentes ahorran tokens. La realidad arquitectónica es distinta: los subagentes no ahorran tokens, los mueven.

La Matemática de la Delegación

Un subagente debe cargar su propio prompt de sistema, herramientas y archivos de memoria.

Caso de estudio Un subagente quema 9,800 tokens (overhead) para realizar una tarea que ahorra 5,700 tokens en la sesión principal. En aislamiento, perdiste dinero.
Multiplicadores de Gasto Los agentes usan 4 veces más tokens que un chat normal, y los sistemas multi-agente pueden usar hasta 15 veces más.

¿Cuándo es rentable?

Solo si se cumplen estas condiciones:

  • La salida es de gran volumen.
  • No necesitas el detalle técnico en el historial principal.
  • La sesión principal va a durar muchos turnos más.
Truco de Arquitecto Configura subagentes en Haiku. Es 5 veces más barato y no invalida el caché de tu sesión principal en Opus/Sonnet.

08 Estrategia 6: Tareas Programadas y la Ventana de 60 Minutos

⏱️

Vampiros nocturnos

Los cron jobs pueden devorar tu cuota mientras duermes

Las tareas de fondo (cron jobs) pueden actuar como "vampiros" nocturnos que devoran tu cuota mientras duermes.

La Regla de Oro del Caché

Vida útil El caché de Anthropic tiene una vida útil de exactamente 60 minutos.
Intervalo de tareaEstado del cachéCoste relativo
Cada 45 minutosEncuentra el caché vivoPagas el 10% del coste
Cada 2 horasEl caché ha expiradoPagas el 100% (10× más caro)

Si tienes una tarea programada, es financieramente más inteligente ejecutarla cada 45 minutos que cada 2 horas.

09 Desmitificación: Errores Comunes y /rewind

💡

Mitos desmontados

Lo que no funciona y por qué

❌ Prompts cortos▶
No ahorran nada. El coste real es la respuesta y el historial, no tu pregunta.
❌ Compactación (Compaction)▶
Es la acción más cara posible. Para resumir, debe leer todo el historial (precio full) y luego borra el caché a propósito.
✅ La alternativa quirúrgica: /rewind▶
Si una tarea salió mal, no compactes. Usa /rewind para volver a un punto donde el caché aún era válido. No requiere relectura y mantiene el ahorro.
❌ PDFs y el "Doble Cobro"▶
Anthropic cobra por el texto del PDF y además toma una captura de pantalla de cada página. Pagas dos veces por la misma información. Convierte siempre a texto plano (.txt) antes de procesar.

11 Cierre y Aplicación Práctica

🎯

Resumen de Conceptos Clave

Los cuatro pilares

  1. Limpieza radical: /clear es tu herramienta de ahorro #1.
  2. Inmutabilidad: No cambies modelo ni esfuerzo durante la sesión.
  3. Filtrado: No permitas que logs de terminal entren al contexto.
  4. Caché inteligente: Alinea tus tareas a la ventana de 60 minutos.
⚠️

Lista de Errores Fatales

Lo que nunca debes hacer

  • Cambiar de Opus a Sonnet para "ahorrar" en una sesión larga (invalida el caché).
  • Subir capturas de pantalla de código en lugar de texto (5k tokens vs 100 tokens).
  • Ignorar el "Doble Cobro" de los PDFs.
🧪

Ejercicios Prácticos

Aprende haciendo

Auditoría Inicial

Ejecuta el Prompt Maestro (sección 02) y detecta si algún archivo de memoria excede los 5k tokens.

Prueba de Estrés de Caché

Realiza una tarea de 10 turnos, mira el /cost. Cambia el modelo y vuelve a mirar el /cost. Verás el salto de 10× en el precio.

Nota Final La IA no está diseñada para ahorrarte tokens; está diseñada para ser útil. Como experto, es tu responsabilidad "mantener tu escritorio limpio" para que la potencia del sistema no se diluya en el ruido.
